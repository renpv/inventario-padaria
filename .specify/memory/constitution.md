# Padaria Inventário & WMS Constitution

## Core Principles

### I. Voice-First UX with Manual Overrides
The primary input method for operations on the shop floor MUST be voice transcription via the Web Speech API. Text inputs and custom button controls (+, -, zero) MUST serve as immediate, seamless fallback mechanisms for accessibility and error correction.

### II. Offline-Resilient & Local-First Rascunhos
All operational inputs (contagens, perdas, sobras, recebimentos) MUST be stored locally (IndexedDB/localStorage) first as drafts. Sincronização to Supabase MUST happen in the background or explicitly upon connection recovery, ensuring zero loss of shop-floor work.

### III. Strict Shift Sequence & Self-Healing
Shift execution MUST respect the configured order. If a shift is skipped, the system MUST run a self-healing process to create a historical "NÃO REALIZADO" entry with justification, ensuring the daily audit trail remains unbroken.

### IV. Mathematical Purchase Order Suggestions
All purchase orders generated by the WMS system MUST mathematically derive from the specified formula: `(Consumo + Mínimo) - (Estoque Atual + Pedidos Enviados)`. No order suggestions should rely on arbitrary placeholders or vibes.

### V. Role & Boundary Segmentation
The application MUST strictly enforce authentication and authorization boundaries:
- Operation: Login-free, PIN-secured session. Write-only limits, read-only for sector check, no re-open or edit permissions.
- Gestão: Individual Google OAuth 2.0. Full CRUD, re-opening shifts, financial reconciliations, and parameter configs.

## Platform Constraints

### Technology Stack & Architecture
- Database: PostgreSQL on Supabase, utilizing RLS (Row Level Security) and triggers for updated_at.
- Frontend: Single Page Application in React compiled as a Progressive Web App (PWA) optimized for mobile-first views.
- API: Direct Supabase client interaction (PostgREST) with Edge Functions reserved exclusively for external effects (email, push notifications).

## Quality & Verification Standards

### Verification Gates
- Unit Tests: Required for calculation rules (estoque atual, consumo, purchase suggestions, self-healing logs).
- Integration/E2E: All critical user journeys (inventário ditado, finalização, checkout, credit limits) must be validated end-to-end.

## Governance

This constitution serves as the source of truth for the Padaria Inventário & WMS project. Amendments to these principles require explicit documentation, an updated version bump, and user ratification.
